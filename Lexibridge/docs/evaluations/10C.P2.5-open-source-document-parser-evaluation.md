## Runtime Findings

Docling:

- Installed into an isolated environment.
- RapidOCR model files started downloading from official ModelScope URLs during synthetic-fixture warmup.
- Conversion then moved into Hugging Face layout model snapshot download/initialization and was interrupted after long runtime.
- No private PDF was used in the warmup.
- No completed parse output was produced, so it cannot be selected from this run.

PaddleOCR PP-StructureV3:

- Initial import succeeded after installing `paddlepaddle`.
- `PPStructureV3` required additional `paddlex[ocr]` dependencies; those were installed into the isolated environment.
- A synthetic-fixture warmup then downloaded official Paddle model files from ModelScope, including document orientation, layout, OCR detection/recognition, table classification, and table structure models.
- The warmup was interrupted during a large table-structure model download. No completed parse output was produced.
- This remains a real deployment concern: first-run model footprint and cold start are substantial.

MinerU:

- Installed and CLI discovery was repaired in the evaluation probe.
- A synthetic-fixture probe reached the MinerU CLI but returned an execution traceback before producing blocks.
- Installed package metadata reports a non-standard license expression, `LicenseRef-MinerU-Open-Source-License`.
- MinerU is not selectable until the license is reviewed and the local CLI execution error is resolved.

## Architecture Comparison

Option 1: Single open-source parser for all PDFs.

Rejected for now. No candidate completed local evaluation, and replacing the stable native/Tesseract path without evidence would increase risk.

Option 2: Route simple born-digital PDFs to native parser, simple scanned PDFs to Tesseract, and complex layout/table/formula PDFs to a selected structure parser.

Preferred architecture once a candidate passes evaluation. It preserves working paths and limits new parser cost to documents that need it.

Option 3: Selected open-source parser as default, native/Tesseract as fallback.

Not supported by this run. Candidate cold-start/model footprint and unresolved execution failures are too large to make a new parser the default.
