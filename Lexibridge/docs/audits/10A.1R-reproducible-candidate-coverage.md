## 4. Why Replay Was Not Executed

The current HEAD cannot replay the historical 10G coverage dataset without
mixing incompatible evidence:

1. Current `backend/lexibridge.db` has zero Formal WorkflowRuns and zero Formal
   Items.
2. Current branch does not include the later 10C candidate governance top-50
   production changes that made full PDFs persist 50 Items instead of blocking
   on item limit.
3. Current branch does not include the 10F/10G real pair-funnel and pair-local
   eligibility code.
4. Historical temp SQLite databases and private item-level JSON artifacts are
   absent from `<LOCAL_PRIVATE_TMP>`.
5. Running the current mainline against the second-course PDFs would not be a
   reproduction of the historical `5 PDFs -> 250 Items -> 2 candidates` result;
   it would be a different experiment on different code.

For these reasons, the audit did not create new Formal Items or simulate the
missing 10G state.

## 10. Provider vs Non-Provider Estimate

Only a broad historical estimate is possible:

  Items after 10G.
- Existing accepted-pair-to-selected matching loss was 18/20 accepted pairs, a
  possible non-Provider repair area if those pair surfaces are useful course

  but current data does not quantify the safe Provider-needed subset.
